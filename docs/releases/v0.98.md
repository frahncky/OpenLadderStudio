# OpenLadder Studio v0.98

## Decodificação do dump 0A no próprio relatório

A v0.97 passou a varrer endereços com o comando de leitura `0A` e registrar a resposta
crua de cada endereço. A v0.98 acrescenta, ao lado de cada resposta, uma linha já
**decodificada**, para o operador ver de imediato quais endereços guardam dados sem precisar
segmentar os bytes à mão.

### Principal mudança

- **motor PG Lab 1.12**: para cada endereço que responde na varredura `0A`, o relatório passa
  a incluir uma linha `DECOD` com o enquadramento da resposta — `CMD=00`, o `LEN` retornado
  e **quantos bytes do payload são não-zero**. Endereços com `nao-zero=0` são área vazia;
  `nao-zero>0` marca dado real a investigar;
- é apenas leitura dos bytes já recebidos — nenhuma transmissão nova é feita.

### Segurança

Sem qualquer efeito sobre o que é transmitido: a decodificação só interpreta a resposta já
capturada. Todas as travas da varredura `0A` (intrínseca a `CMD=0A`, modo READ-ONLY, limite
de leituras, denylist por quadro, parada no silêncio) permanecem. `0F 00 F0` segue bloqueado
e o `38 00 C7` segue exigindo F0 validado.

### Uso

Rode o Teste Único e procure no relatório as linhas `DECOD 0xXXXX: CMD=00 LEN=… nao-zero=…`.
A sequência de endereços com `nao-zero>0` é o mapa das regiões de memória com conteúdo, ponto
de partida para localizar o programa do usuário.
