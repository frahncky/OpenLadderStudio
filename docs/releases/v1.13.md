# OpenLadder Studio v1.13

## Recuperação de sessão antes do primeiro PG33 físico

A v1.12 confirmou em bancada que o backup completo do TP02 pode ser lido antes da prova de escrita, mas mostrou uma nova condição intermitente: após o backup e a preparação do quadro `0x33`, a reabertura da COM para o preflight de escrita perdeu o enlace PG antes da transmissão.

### Evidência física observada

No teste real:

- o snapshot inicial acabou sendo lido com sucesso;
- o programa canônico de 23 passos / END=0022 foi confirmado;
- o quadro PG33 foi preparado;
- a falha ocorreu no `write-preflight`, durante HELLO;
- **o comando 0x33 não foi transmitido**.

### Correção

A rotina de preflight de escrita agora pode abrir até **3 sessões PG completas** antes do primeiro `0x33`:

1. warm-up somente com `CON-ICB<CR>`;
2. abertura limpa da COM em `19200 8O1, DTR=OFF, RTS=OFF`;
3. confirmação de HELLO/STOP;
4. `F0`;
5. `38`;
6. somente depois disso o PG33 é liberado.

Os tempos de estabilização aumentam por sessão: 1800 / 2200 / 2600 ms.

### Regra de segurança principal

Os retries de sessão acontecem **somente antes da primeira transmissão do PG33**.

Assim que houver uma tentativa real de `0x33`:

- não é aberta outra sessão para retransmitir automaticamente;
- se o ACK não puder ser validado, o resultado é tratado como inconclusivo;
- o log é preservado para análise;
- não ocorre nova escrita automática.

Isso evita repetir uma escrita quando o PLC pode ter aceitado o quadro e perdido apenas a resposta.

### Guardas preservados

- PLC deve estar em STOP;
- programa deve ser exatamente a assinatura canônica de 23 passos / END=0022;
- backup é salvo antes da escrita;
- EXTERNAL continua restrito ao plano seguro confirmado para este programa;
- eco do próprio `0x33` não é aceito como ACK;
- nenhum Clear All, RUN/STOP remoto, `0x09` ou WBP é enviado;
- readback continua obrigatório quando o ACK físico é confirmado.
