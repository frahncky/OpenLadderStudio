# OpenLadder Studio v1.36

## RUN remoto pelo TP-232PG — primeira validação física controlada

A v1.36 implementa o primeiro caminho produtivo, porém ainda **pendente de validação física**, para colocar o WEG TP02 em RUN pelo protocolo PG/TP-232PG.

A identificação do quadro veio de análise estática reproduzível do `pc12.exe` original. O construtor em `0x0046F4FA` monta `02 00 FD`. Seus chamadores ficam na função `0x004AE5DC..0x004AE836`, e o mesmo handler referencia a mensagem `PLC Mode: Running`. O handler adjacente `0x004AE836..0x004AEA95` usa `01 00 FE` e referencia `PLC Mode: Program`, reforçando a separação RUN/Program.

Essa evidência é forte, mas não substitui o ensaio no TP02 real. Por isso a v1.36 trata o primeiro uso como validação física protegida.

## Guardrails do RUN

Ao clicar em **RUN**:

1. o software exige conexão prévia com o TP02;
2. antes de qualquer mudança de estado, requalifica o PLC em **STOP** por `HELLO + F0` na mesma porta aberta;
3. exibe uma confirmação explícita alertando que o programa pode energizar saídas físicas;
4. somente após confirmação transmite `02 00 FD` **uma única vez**;
5. o software não usa a resposta imediata do quadro como prova de sucesso;
6. fecha a sessão de comando e verifica o estado novamente usando somente o HELLO já conhecido;
7. RUN só é declarado quando o HELLO retorna o vetor físico conhecido `C0 01 09 35`;
8. se o HELLO retornar `80 01 09 75`, o software informa que o TP02 permaneceu em STOP;
9. se a comunicação falhar depois da transmissão, o estado passa a **desconhecido**, a conexão lógica é invalidada e o RUN **não é retransmitido**.

Se o TP02 já estiver em RUN durante o preflight, nenhum quadro de mudança de estado é enviado.

## STOP permanece protegido

Embora a mesma análise estática associe `01 00 FE` ao handler `PLC Mode: Program`, a v1.36 **não habilita STOP remoto**. O botão STOP continua sem transmitir bytes até uma validação independente.

## O que não mudou

- `0F 00 F0` (Clear All Memory) continua bloqueado;
- escrita `0x09`, WBP e firmware continuam fora do fluxo PG produtivo;
- WRITE continua exigindo STOP e qualificação completa;
- VERIFY continua somente leitura;
- não existe retransmissão cega após PG33 ou RUN;
- CONECTAR, LER e reconstruir o Ladder mantêm o comportamento validado nas versões anteriores.

## Estado de validação

Compilação e testes automatizados verificam o fluxo e os guardrails, mas **não comprovam a semântica física de `02 00 FD`**. A validação física exige um teste controlado no TP02 real e sucesso somente será registrado quando, após o único TX, o HELLO confirmar `C0 01 09 35`.
