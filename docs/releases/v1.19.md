# OpenLadder Studio v1.19

## Recuperacao ampliada do link PG antes da prova de alteracao

A v1.18 manteve todas as protecoes de escrita e nao chegou a transmitir o PG33 TESTE em uma bancada onde o enlace HELLO nao foi confirmado apos tres rodadas. O proprio dialogo confirmou que o PLC nao foi alterado.

A v1.19 corrige especificamente a fase de aquisicao do TP-232PG antes de qualquer escrita.

### Aquisicao ampliada

A rotina agora usa somente 19200 8O1, mas varre de forma controlada os estados das linhas:

1. DTR=OFF / RTS=OFF;
2. DTR=ON / RTS=OFF;
3. DTR=ON / RTS=ON.

O perfil OFF/OFF continua sendo o primeiro e recebe o maior numero de tentativas.

Se o primeiro ciclo nao confirmar HELLO, a interface faz reacondicionamento das linhas DTR/RTS sem transmitir bytes e repete a varredura.

Quando `80 01 09 75` ou `C0 01 09 35` e confirmado, a mesma `SerialPort`, com o mesmo perfil que respondeu, permanece aberta para o caminho critico:

`HELLO valido -> F0 -> 38 -> 34 -> backup -> PG33`

### Mais margem antes de qualquer escrita

A prova alterar+restaurar e os readbacks podem tentar ate cinco rodadas de aquisicao antes de desistir.

Essas tentativas extras acontecem apenas quando nenhum PG33 foi transmitido. Assim que uma escrita real ocorre, permanecem as regras anteriores de transmissao unica e ausencia de retry cego.

### Seguranca preservada

- PLC obrigatoriamente em STOP;
- nenhuma tentativa de escrita enquanto HELLO/F0/38/34 nao estiverem confirmados;
- programa original salvo antes da primeira alteracao;
- PG33 TESTE transmitido no maximo uma vez;
- PG33 RESTORE transmitido no maximo uma vez;
- ACK fisico exigido: `00 00 FF`;
- nenhum Clear All;
- nenhum RUN/STOP remoto;
- nenhum WBP;
- em falha antes do PG33, o PLC permanece inalterado.

A meta desta versao e eliminar o estado residual/intermitente do TP-232PG entre sessoes sem relaxar nenhuma protecao de escrita.
