# OpenLadder Studio v1.52 — gravação PG33 multibloco

## Por que esta versão existe

A trava anterior de 80 machine words não representa o limite do programa inteiro. Ela representa o maior **bloco PG33 individual** já reconstruído no caminho `Write PLC Program` do PC12.

A análise estática e as emulações offline já existentes no repositório mostram o comportamento completo do PC12:

- cada instrução lógica ocupa `StepSpan = 1..4` machine words;
- o PC12 fecha um bloco quando atinge **20 instruções lógicas**;
- por isso um bloco pode conter de 1 a 80 machine words;
- o quadro `0x33` carrega o endereço inicial real do bloco em `START_H/START_L`;
- após um bloco aceito, o PC12 preserva o cursor real de passos e prepara o bloco seguinte;
- o processo continua até o cursor atingir o tamanho total do programa.

Assim, um projeto de 323 machine words não deve ser enviado como um quadro gigantesco. Ele deve ser dividido em vários quadros PG33, cada um respeitando o envelope `20 instruções / até 80 words`.

## Implementação produtiva

A v1.52 adiciona um planejador multibloco ao fluxo de **ESCREVER**.

O compilador continua usando exatamente o subconjunto que já possuía validação física no caminho produtivo:

- contatos Boolean X/Y/C;
- saídas Y/C;
- TMR/CNT com preset literal;
- SET/RST Y;
- F-13w ADD com D,D,literal;
- F-00 END.

A diferença é que o limite de 20 instruções deixa de ser aplicado ao programa inteiro e passa a ser aplicado a **cada bloco**, como no PC12 original.

Para cada bloco, a v1.52 monta:

```text
33
LEN = 3*W + 4
00
START_H
START_L
2*W
[HIGH,LOW] x W
[EXTERNAL] x W
CHECKSUM
```

onde `W` é a quantidade de machine words do bloco (1..80).

## Compatibilidade com projetos pequenos

Projetos que cabem em um único bloco continuam usando o caminho legado `RunProjectWriteV123`, que é o fluxo já comprovado fisicamente no TP02.

Somente projetos com dois ou mais blocos entram no novo orquestrador multibloco.

## Segurança do multibloco

Antes do primeiro bloco:

1. o PLC precisa estar em STOP;
2. o enlace é qualificado pelo caminho PG já existente;
3. F0 e 38 são executados como no fluxo validado;
4. o programa existente é lido e salvo como backup;
5. o plano completo de blocos é salvo em arquivo de sessão.

Durante a gravação:

- todos os blocos usam a mesma sessão serial aberta;
- cada bloco é transmitido **uma única vez**;
- cada bloco precisa receber o ACK físico conhecido `00 00 FF`;
- depois de um ACK, o cursor avança para o endereço real do bloco seguinte;
- não existe retransmissão cega de um bloco quando o resultado do TX é incerto;
- se uma falha ocorrer depois que qualquer bloco puder ter ido ao fio, a sequência inteira é abortada.

Depois da sequência:

- o Studio fecha a sessão de escrita;
- reacquire o TP02 em STOP;
- relê o programa;
- compara o readback com o projeto compilado.

## Restore multibloco

A v1.52 **não faz restore multibloco automático**.

Isso é deliberado. O restore automático de um programa longo ainda não possui validação física independente. Se houver divergência depois da sequência ou se o readback ficar indisponível, o backup permanece salvo e o software manda manter o PLC em STOP. Nenhum bloco é reenviado e nenhum restore cego é executado.

O caminho legado de bloco único mantém suas proteções anteriores.

## VERIFY para projetos longos

O botão **VERIFICAR GRAVAÇÃO** agora prepara a referência usando o mesmo planejador v1.52. Portanto, ele deixa de bloquear apenas porque o projeto possui mais de 80 words.

VERIFY continua somente leitura: não transmite PG33 e não restaura o programa.

## Projeto de 323 words

O projeto de fronteira criado na v1.51 possui:

- 323 machine words;
- 161 rungs Boolean + END;
- nenhuma saída física Y;
- END global no passo 322.

Como cada rung Boolean do projeto ocupa duas instruções de um word (`STR` + `OUT C`) e END ocupa uma, o planejador PG33 não o transforma em cinco blocos de 80 words. O limite real é **20 instruções lógicas por bloco**. Portanto a sequência esperada possui vários blocos menores, com `START` crescente pelo cursor real do programa.

Essa gravação permitirá depois usar a leitura PG34 longa da v1.51 para provar fisicamente as páginas 0, 80, 160, 240 e 320.

## Evidência usada

A implementação se apoia em evidência já reprodutível no repositório:

- `scripts/analyze_pc12_write_tx.py` — construtor e campos do quadro 0x33;
- `scripts/analyze_pc12_pg33_encoder_fields.py` — origem dos campos e StepSpan;
- `scripts/emulate_pc12_pg33_record_boundary.py` — 20 instruções por bloco e avanço do cursor;
- `scripts/emulate_pc12_pg33_builder.py` — quadro real do PC12, W=1..80;
- `scripts/emulate_pc12_pg33_success_tail.py` — retorno ao próximo bloco com cursor preservado;
- `src/OpenLadderStudio.Core/Tp02Pg33DryRunFrame.cs` e `Tp02Pg33DryRunProgram.cs` — modelo offline consolidado.

Nenhuma dessas análises, por si só, substitui a validação física do novo fluxo multibloco. O primeiro teste no TP02 deve continuar sendo feito em bancada segura, com PLC em STOP e sem cargas perigosas.
