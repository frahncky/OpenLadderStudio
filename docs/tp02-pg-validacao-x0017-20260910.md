# Validação física — X0017 aberto (2026-09-10 13:26 BRT)

## Objetivo

Registrar a captura `TP02-PG-Lab-20260910-132650.txt`, obtida com **OpenLadder Studio v1.04 / TP02 PG Lab 1.16**, PLC em STOP e fluxo estritamente READ-ONLY.

Programa ensaiado:

```text
X0017 aberto -- (Y0003)
```

Este teste foi escolhido para observar o segundo salto de grupo de endereço após as capturas de X0001 e X0009.

## Sessão válida

Na sessão 2, após quatro HELLOs silenciosos, o quinto HELLO confirmou STOP e a sequência conhecida completou:

```text
HELLO -> 80 01 09 75
F0    -> 00 02 10 22 CB
38    -> 00 02 00 02 FB
34    -> quadro de 243 bytes, LEN=F0, payload=240 bytes, checksum válido
```

O checksum final do quadro 34 foi `0x90`.

## Payload 34 observado

Os únicos bytes não nulos do payload foram:

```text
payload[0x000] = 02
payload[0x001] = 10
payload[0x002] = 20
payload[0x003] = 42
payload[0x0A0] = 03
payload[0x0A1] = 08
```

Pela geometria conhecida:

```text
passo i:
  HIGH = payload[2*i]
  LOW  = payload[2*i+1]
  BRAW = payload[0x0A0+i]
```

resulta:

```text
passo 0: HIGH=02 LOW=10 BRAW=03   -> STR X0017
passo 1: HIGH=20 LOW=42 BRAW=08   -> OUT Y0003
```

## Segundo salto de grupo confirmado

Comparando os três inícios de grupo já observados com contato aberto e índice de bit zero:

```text
X0001: HIGH=00 LOW=10 BRAW=01
X0009: HIGH=01 LOW=10 BRAW=02
X0017: HIGH=02 LOW=10 BRAW=03
```

Portanto, o hardware confirma que o plano A evolui por grupos de oito entradas:

```text
group = (n - 1) >> 3
bit   = (n - 1) & 0x07

para STR Xn observado:
HIGH = group
LOW  = 0x10 | bit
```

A captura X0017 é a segunda fronteira física além do primeiro grupo e coincide exatamente com a fórmula usada atualmente pelo encoder para HIGH/LOW.

## Comparação controlada X0009 -> X0017

Mantendo o mesmo opcode STR, o mesmo índice de bit dentro do grupo (bit 0) e a mesma bobina Y0003:

```text
X0009: HIGH=01 LOW=10 BRAW=02 checksum=92
X0017: HIGH=02 LOW=10 BRAW=03 checksum=90
```

Mudaram apenas:

```text
payload[0x000]: 01 -> 02   (+01)
payload[0x0A0]: 02 -> 03   (+01)
checksum:        92 -> 90   (-02)
```

O checksum acompanha exatamente os dois incrementos do payload.

## Consequência para o modelo de endereçamento

Para os três primeiros inícios de grupo observados, o padrão é agora físico e não apenas inferido:

```text
X0001 -> grupo 0 -> HIGH 00
X0009 -> grupo 1 -> HIGH 01
X0017 -> grupo 2 -> HIGH 02
```

O LOW reinicia em `0x10` a cada início de grupo para STR aberto.

Isso reforça fortemente que HIGH carrega o grupo de oito entradas no plano A, enquanto os três bits inferiores de LOW carregam a posição dentro do grupo.

## Região B bruta

Nos mesmos três inícios de grupo:

```text
X0001: BRAW=01
X0009: BRAW=02
X0017: BRAW=03
```

Assim, para **bit 0 nos grupos 0, 1 e 2**, BRAW também avançou uma unidade por grupo.

Isso é uma nova regularidade física importante, mas não permite ainda declarar uma fórmula geral para BRAW. Há contraexemplos de contexto/instrução já conhecidos, e a transformação entre BRAW bruto e a representação interna usada pelo decoder do PC12 continua não resolvida.

## Comando 38

O retorno foi:

```text
00 02 00 02 FB
```

Esse é o mesmo valor observado em outros programas mínimos de um contato + bobina, inclusive X0009 -> Y0003. Portanto, nesta família mínima, mudar o endereço do contato entre X0009 e X0017 não alterou `38 PAYLOAD[1]`.

Isso reforça que o byte variável do 38 parece refletir alguma grandeza estrutural mais grossa do programa, e não simplesmente o endereço do contato. A semântica exata permanece desconhecida.
