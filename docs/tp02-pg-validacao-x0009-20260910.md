# TP02 PG — validação de bancada de X0009

Data: 2026-09-10 11:18 BRT

## Objetivo

Validar em hardware o primeiro ponto em que a antiga aproximação linear de endereço e o encoder reconstruído do PC12 divergem.

Programa de teste:

```text
X0009 aberto -- (Y0003)
```

Condições:

```text
PLC: STOP
OpenLadder Studio: v1.04
TP02 PG Lab: 1.16
Serial: 19200 8O1, DTR=ON, RTS=OFF
Fluxo: HELLO -> F0 -> 38 -> 34
Modo: READ_ONLY
```

Arquivo de bancada: `TP02-PG-Lab-20260910-111814.txt`.

## Sessão válida

Após várias sessões silenciosas, a sessão 8 obteve:

```text
HELLO -> 80 01 09 75
F0    -> 00 02 10 22 CB
38    -> 00 02 00 02 FB
34 TX -> 34 03 00 00 A0 28
```

O retorno do `34` foi um quadro válido de 243 bytes:

```text
FLAGS = 0x00
LEN   = 0xF0 = 240 bytes
CHECKSUM final = 0x92
sum(quadro) mod 256 = 0xFF
```

O PG Lab salvou os dumps de frame e payload com timestamp `20260910-111814`.

## Payload observado

Bytes não nulos do payload de 240 bytes:

```text
offset 0x000 = 0x01
offset 0x001 = 0x10
offset 0x002 = 0x20
offset 0x003 = 0x42
offset 0x0A0 = 0x02
offset 0x0A1 = 0x08
```

Pela geometria em dois planos:

```text
passo 0 (contato): HIGH=0x01 LOW=0x10 B=0x02
passo 1 (bobina):  HIGH=0x20 LOW=0x42 B=0x08
```

## Comparação controlada com X0001 aberto -> Y0003

Captura anterior de `X0001 aberto -> Y0003`:

```text
passo 0: HIGH=0x00 LOW=0x10 B=0x01
passo 1: HIGH=0x20 LOW=0x42 B=0x08
```

Nova captura `X0009 aberto -> Y0003`:

```text
passo 0: HIGH=0x01 LOW=0x10 B=0x02
passo 1: HIGH=0x20 LOW=0x42 B=0x08
```

Somente dois bytes do payload mudaram:

```text
payload[0x000]: 00 -> 01
payload[0x0A0]: 01 -> 02
```

O byte `LOW` do contato permaneceu `0x10`. A bobina Y0003 permaneceu integralmente inalterada.

## Conclusões

### 1. Aproximação linear antiga refutada

A antiga regra empírica local:

```text
payload LOW ~= 0x0F + n
```

previa `0x18` para X0009. O hardware retornou `0x10`.

Portanto, a aproximação linear observada em X0001/X0002 não é uma fórmula geral.

### 2. Encoder do PC12 confirmado no plano A para X0009

`Tp02TargetCompiler.EncodeBitInstruction("STR", "X", 9)` produz, para os dois primeiros bytes da palavra:

```text
HIGH = 0x01
LOW  = 0x10
```

Esses dois bytes coincidem exatamente com a captura física.

O ponto de fronteira de grupo foi, portanto, validado em hardware: ao passar de X0008 para X0009, o índice de bit em `LOW` reinicia e o grupo passa a aparecer em `HIGH`.

### 3. A interpretação direta da Região B precisa ser corrigida

A documentação anterior afirmava que, no quadro bruto do `34`, os bits altos do endereço de X0009 apareceriam diretamente em `B & 0x10/0x20/0x40`.

Isso não aconteceu. O byte bruto correspondente da Região B foi:

```text
B = 0x02
```

Logo, não há `0x10` aceso nesse byte.

Isso não invalida o fato de que o `pc12.exe` possui uma rotina que testa bits `0x10/0x20/0x40` de um byte associado ao segundo cursor durante a reconstrução do número. O que a bancada refuta é a hipótese de que esse byte interno seja, sem transformação, exatamente o `payload[0x0A0+i]` bruto recebido do PLC.

A partir desta captura, devemos distinguir explicitamente:

1. **geometria bruta do quadro 34** — confirmada: dois bytes na Região A e um byte na Região B por passo;
2. **palavra produzida pelo encoder do PC12** — HIGH/LOW de X0009 confirmados em bancada;
3. **representação interna usada pelo decodificador do PC12** — ainda precisa ser rastreada entre o buffer de recepção e a rotina de reconstrução do número;
4. **semântica do byte bruto da Região B** — continua apenas parcialmente conhecida.

## Efeito sobre o modelo atual

Estado após este teste:

```text
CONFIRMADO EM BANCADA:
- X0009 aberto tem HIGH=01 e LOW=10 no plano A;
- Y0003 permanece HIGH=20 e LOW=42;
- Região B bruta do passo de X0009 = 02;
- 38 voltou a 00 02 00 02 FB neste programa mínimo;
- quadro 34 válido, LEN=F0, checksum FF.

REFUTADO:
- fórmula linear geral LOW=0x0F+n;
- previsão de que X0009 exigiria diretamente B&0x10 no byte bruto payload[0x0A0].

MANTIDO:
- geometria de 80 passos em dois planos;
- opcodes booleanos recuperados;
- HIGH/LOW do encoder para X0009;
- política READ_ONLY.

EM ABERTO:
- transformação entre Região B bruta e o byte usado pela rotina interna de reconstrução de endereço;
- significado dos bits baixos da Região B bruta;
- origem completa da classe X/Y/C no caminho booleano.
```
